## R2-1：504 与连接池耗尽

GET 增加 504，仍最多三次；POST 等写请求不自动重试。遇到 Envoy overloaded/UO/connection_pool_overflow 或响应体中的 reset reason: overflow 立即返回，保留原响应正文；本地连接池耗尽、文件描述符耗尽和取消/超时也不重试。测试覆盖 504 三次、各种过载信号只一次、响应体与 Close 完整保留。

## R2-2：实测大分页与超时

AIS 顺序请求，各接口每环境 5 次，`page_size=1000`，全部 HTTP 200：

| 环境 | API | 中位数 / 最大值（秒） |
| --- | --- | --- |
| D | IAM users | 0.182 / 0.567 |
| D | ECS VM | 0.344 / 0.526 |
| D | compute nodes | 0.104 / 0.397 |
| PT | IAM users | 0.075 / 0.518 |
| PT | ECS VM | 0.040 / 0.071 |
| PT | compute nodes | 0.037 / 0.096 |

compute nodes 将请求的 1000 条限制为 100 条；IAM users 确实返回 1000 条。30 次样本不足以估计 P99。选择 20s 单次请求上限，覆盖需求文档中的网关默认 15s 并留 5s 余量；不因为此次短样本快速返回而把超时调短。实测 HTTPRoute 还存在显式 35s / 120s 等特例（IAM IDP 为 request=120s），20s 是 CLI 的有界等待预算，并不声称覆盖所有网关配置。客户端超时与上下文取消仍只发起一次请求。三处平台客户端构造均使用同一工厂。

## R2-3：跨 profile / VC 的共享并发与 429

实测读取 D 环境 7 个 BackendTrafficPolicy、5 个 EnvoyProxy 及 HTTPRoute：策略配置网关自身重试 2 次，没有显式 per-client rateLimit；Envoy 的 concurrency=4/16 是工作线程数，不能据此推导请求 QPS。大分页探测的 30 次请求没有 429 或限流响应头。

保留上层任务编排的 6 / 32 / 24 等 worker 数，在 HTTP 传输入口对同一 origin 的所有 profile/VC 请求共同限制为最多 6 个在途请求，直到响应体关闭才归还名额；这只是保守客户端预算。429 支持 Retry-After 秒数和 HTTP 日期，指数退避加正向抖动，跨并发请求共享冷却并错开恢复；过长 Retry-After 不在单个重试循环中长时间等待。取消能中断排队与冷却。测试覆盖 32 worker 峰值 <=6、响应体持有名额、共享冷却、错开恢复、Retry-After 下限与取消。

## R2-4：IAM 页码分页

D/PT 的 IAM users 大页实测 next_page_token="2"，不是稳定快照游标。平台没有在现有契约中提供可验证的稳定 keyset/snapshot 参数，因此保留页码 API，固定整次扫描的 page_size，用户/组/角色/绑定策略按稳定身份去重，对 total_size 漂移和缺行做校验；发现不稳定重新完整读取一次，再次不完整明确返回错误。循环 token 立即报不完整，无进展页有界结束。已覆盖用户目录、用户所属组、组成员、用户组目录、角色、自己的角色、绑定策略与过滤用户查询。策略去重键包含 policy ID + scope + member，保留同一策略对不同成员的授权。

测试模拟增删导致 total_size 变化、重叠页、稳定重读、持续缺行、无进展与 token 循环；另用真实页码偏移模拟 150 条有限查询，确认后续页不缩小 page_size。单条资源 scope 的精确匹配仍提前返回；未宣称页码 API 能提供数据库事务快照。
