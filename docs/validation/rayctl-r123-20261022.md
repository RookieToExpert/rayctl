## R2-1：504 与连接池耗尽

GET 增加 504，仍最多三次；POST 等写请求不自动重试。遇到 Envoy overloaded/UO/connection_pool_overflow 或响应体中的 reset reason: overflow 立即返回，保留原响应正文；本地连接池耗尽、文件描述符耗尽和取消/超时也不重试。测试覆盖 504 三次、各种过载信号只一次、响应体与 Close 完整保留。

## R2-2：实测大分页与超时

AIS 顺序请求，各接口每环境 5 次，`page_size=1000`，全部 HTTP 200：

| 环境 | API | 中位数 / 最大值（秒） |
| --- | --- | --- |
| D | IAM users | 0.182 / 0.567 |
| D | ECS VM | 0.344 / 0.526 |
| D | compute nodes | 0.104 / 0.397 |
| PT | IAM users | 0.075 / 0.518 |
| PT | ECS VM | 0.040 / 0.071 |
| PT | compute nodes | 0.037 / 0.096 |

compute nodes 将请求的 1000 条限制为 100 条；IAM users 确实返回 1000 条。30 次样本不足以估计 P99。选择 20s 单次请求上限，覆盖需求文档中的网关默认 15s 并留 5s 余量；不因为此次短样本快速返回而把超时调短。实测 HTTPRoute 还存在显式 35s / 120s 等特例（IAM IDP 为 request=120s），20s 是 CLI 的有界等待预算，并不声称覆盖所有网关配置。客户端超时与上下文取消仍只发起一次请求。三处平台客户端构造均使用同一工厂。
