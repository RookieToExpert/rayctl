# IAM 授权预检分页故障回归（2026-10-22）

用户命令：`rayctl auth grant afs afs-sunlihao -r owner -u sunlihao`。先前新增的完整性校验在两次相同的页码扫描后仍返回缺行错误，导致授权预检无法完成。

## 真实接口核对

在 AIS 使用现有 D/PT 配置，只执行只读请求和 `--dry-run`。

- D 的 `bindingPolicies` 实时 `total_size=2768`。固定 100 条分页的两次完整扫描均收到原始 2768 行，但唯一绑定仅有 2754、2756 条，集合指纹也不同；重复行均跨相邻页。直接复现原命令的预检同样失败，唯一绑定为 2753 条。这是翻页重复且漏行，不能关闭完整性校验后继续。
- 现有排序为 `create_time desc`。同创建时间的绑定缺少稳定排序；单独 `id desc` 和复合 `create_time desc, id desc` 均被真实接口拒绝（HTTP 500），未将这些参数用于产品代码。
- 请求 5000 条会被服务端裁剪到 1000 条。明确请求 1000 条时，D 的两次完整扫描均为 `[1000, 1000, 768]`，2768 个唯一绑定、2408 个不同 policy ID，集合指纹相同；分别耗时 1.480s 和 0.970s。

## 修复

1. 授权预检使用已经解析的完整资源 scope 过滤绑定策略，再保持原有的 scope、成员、角色精确匹配；不必先扫描全租户策略。过滤仍兼容 `/rm` 前缀差异，并保留同一 policy ID 的不同成员。
2. 绑定策略首次扫描仍为固定 100 条。校验发现缺行或计数变化时，从第一页以固定 1000 条重扫一次；不在一次页码扫描中调整大小，不合并两次可能不同的快照。再次缺行仍返回错误。用户、组和角色的页大小保持原行为。
3. 警告改为“分页存在重复或计数不一致”，避免把服务端排序问题直接表述为数据发生增删。

这是有界的恢复策略，页码 API 本身仍不提供事务快照。
