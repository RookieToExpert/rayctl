## ATE-01：不存在的任务应尽快返回“未找到”

- 状态：已修复并在 AIS D/PT 验收（2026-10-22）。
- 来源：2026-10-22 用户补测；旧版同样存在，不属于本轮 R3-2 回归。
- 现象：`ate get <不存在的任务名>` 在 20 秒查询预算下等满超时，最后报“查询超时”，不能及时返回“任务不存在”。
- 根因：平台未命中后多次下载 HC 全量 Job/Pod 对象，重复扫描耗尽查询预算；部分查询错误被丢弃，后端阶段超时也会误报为整个命令超时。

验收要求：

1. 必要查找范围均成功完成且没有匹配时，尽快明确返回“任务不存在”，不等待完整查询超时。
2. 后端超时、权限不足或只完成部分扫描时，保留真实错误，不能误报“任务不存在”；取消仍能中断查询。
3. 保留已有任务名、Pod 名、UID，以及跨 namespace/VC 查找和歧义提示的行为。
4. 补充“不存在快速返回”和“真实超时不误分类”的回归测试；从当前 list 选择存在的任务，并使用确认不存在的名称，在 AIS 只读复验、记录耗时。

修复与实测证据见 [ATE 不存在查询验收记录](validation/rayctl-ate-not-found-20261022.md)。

## UX-01：`get -l` 只输出默认输出里没有的内容

- 状态：已实现，`5cfed1d`；补漏 `a0f7b55`、`1f8aa72`。AIT/AID/ATE/AIR/gateway 已做 AIS 复验，其余详情路径有输出回归测试。
- 现象：`ait get <job> -l` 重印默认摘要；`air job get <job> -l` 重印默认字段后继续输出大量详情，查问题时先看到重复内容。
- 范围：有 `-l` 的只读 get/详情命令，包括 AIT、AID、ATE、AIR job/gateway、AFS、Pod、Node 的适用详情路径。list 的 `-l` 仍按加列处理；不改变修改类命令的 `-l`。

验收要求：

1. 表格模式先输出一行身份锚点：名称、状态、host namespace、节点；缺失信息明确显示未采集/不适用。之后仅输出默认视图未出现的字段和段落。
2. UID、IMAGE PULL SECRET 等仅在 `-l` 出现的字段归入增量段；多对象每个对象均有锚点。
3. JSON 仍输出完整的已采集对象，不受表格增量展示或隐藏噪音的过滤影响。保持原有查询深度和字段语义。
4. 合并 PVC 映射和 Pod 挂载中的重复资源信息；保留各容器的 mount path、subPath、只读等独有证据，不能为了去重而丢掉挂载差异。
5. 默认隐藏平台注入卷，或折叠成一行数量：serviceaccount projected、`/etc/hosts`、`vcluster-rewrite-hosts` 等。空日志不输出空标题；AIT 不显示与其无关的“采样间隔约 30s”警告。
6. 更新命令帮助和 README；测试单对象、多对象、无日志、注入卷、重复 PVC，以及 JSON 完整性。

实现方向：在各领域 output 文件中区分摘要和增量段，JSON 捕获在展示过滤之前完成，不修改服务层返回对象来实现隐藏。
